# GitHub 加速下载

当前版本：**v1.2.5**

为 GitHub 的**源码压缩包**与 **Release 资产**链接提供右键「GitHub 加速下载」——
按 `加速前缀 + 原链接` 生成新地址，直接触发浏览器下载，不打断当前页面。

```
原始：https://github.com/qingjian-team/qingjian/archive/refs/tags/v0.1.4.zip
加速：https://加速前缀网址/https://github.com/qingjian-team/qingjian/archive/refs/tags/v0.1.4.zip
```

## 安装

### 方式一：加载已解压的扩展程序（推荐，自用）

1. 打开 `chrome://extensions/`
2. 右上角开启**开发者模式**
3. 点击**加载已解压的扩展程序**，选择 `githubjiasu` 目录（即包含 `manifest.json` 的那一层）
4. 建议在工具栏右键图标把它**固定**，之后点图标即可直接打开设置页

### 方式二：.crx扩展插件

第三方Chromium浏览器 百分浏览器 可以使用，官方的 chrome 因为没有上架所以不支持 

### 为什么 .crx 拖不进去？

chrome 如果拖入 `.crx` 提示「程序包无效：`CRX_REQUIRED_PROOF_MISSING`」——**这不是文件损坏**。

品牌版 Chrome 只信任 Chrome Web Store 用 Google 私钥签发的扩展包，自签名包（包括 Chrome
自己用 `--pack-extension` 生成的合法 CRX3）一律拒收。请改用上面的方式一

## 使用

### 右键加速下载

在 GitHub 页面右键点击以下链接时，菜单中会出现加速选项：

- 源码压缩包 `/{owner}/{repo}/archive/...`（`zip` / `tar.gz` / `tgz`）
- `/{owner}/{repo}/zipball/...`、`/tarball/...`
- Release 资产 `/{owner}/{repo}/releases/download/...`
- 最新版资产 `/{owner}/{repo}/releases/latest/download/...`
- `codeload.github.com` 直链

普通链接（issues、blob 页面、站外地址）**不会**出现该菜单项。

菜单是平铺的，默认前缀排在最上方，其余紧随其下：

```
默认（Cf v4）
─────────────
Cf v4/v6
Fy v4
Aw v4
```

点哪个就用哪个前缀下载；只配置一个前缀时不会出现分隔线。

页面内命中的链接旁还会显示一个 `⇣` 按钮，点它同样走默认前缀下载。

### 设置页

点击工具栏图标进入，共四块内容。

**① 新增前缀**

填入加速前缀地址，可选填备注名（不填则自动取域名）。最多 20 条。


**② 已配置前缀**

每条前缀可单独**测速**、**编辑**、**删除**、**设为默认**。

- 「全部测速」逐个实测各前缀的**下载速度**与**首包延迟**，最快的会标绿
- 「按速度排序」按速度从快到慢重排，便于判断本地网络下哪个节点更合适
- 测速目标建议填 **1–5 MB** 的压缩包链接；测速会实际下载约 4 MB，不是 ping，反映真实可用性
- 首次测速会弹出权限申请（仅针对所测前缀的域名），选择「允许」即可

**③ GitHub520 Host**

点按钮在新标签页打开 GitHub520 提供的 GitHub 加速 IP 列表（走当前默认前缀，直连受限时也能打开）。

> 这些 IP 需要你自己写入系统 hosts 文件或代理规则才会生效，扩展本身不修改系统 hosts。

**④ 链接转换测试**

粘贴一条 GitHub 下载链接，实时预览拼接结果，纯本地计算不会发起请求。


## 常见问题

**右键菜单没出现？**

- 确认链接是源码压缩包或 Release 资产，普通链接不显示是正常的
- 确认页面在 `github.com` 域内
- 刚改过配置？点扩展卡片上的刷新图标

**测速全部失败？**

- 首次会弹权限申请，必须点「允许」
- 测速目标过小（< 1 KB）会被判为失败，换成 1–5 MB 的压缩包
- 每个前缀的失败原因会单独显示在对应行

**下载速度没变化？**

- 先测速换一个节点试试
- 部分加速服务会校验 Referer，换一个前缀即可

**会泄露我的浏览记录吗？**

不会。扩展不代理任何流量、不上传任何数据，只做本地 URL 拼接；
配置保存在浏览器本地存储中。
